## Scope

This document tracks remaining chemistry-aware operations over `MoleculeAst`.
It carries forward Phase 11a and Phase 12 from doc 086 using the current module
and type names.

The operation boundaries are:

- resolution fills undetermined state using a chemistry model;
- transformation rewrites one resolved representation into another;
- validation checks integrity, model-independent invariants, and
  model-dependent conformance without mutation.

The boundaries and validator composition established by docs 096 and 118 remain
in force.

## Implicit and explicit hydrogen transformations

Add the model-independent transformer pair under `umol-graph/src/ops/transform`:

### `ToExplicitHydrogens`

- For an atom with literal implicit-hydrogen count `n > 0`, add `n` hydrogen
  atoms and `n` localized single bonds.
- Set the source atom's implicit-hydrogen field to literal zero.
- Leave undetermined or non-literal counts unchanged.
- Reapplying the transformer is a no-op.

### `ToImplicitHydrogens`

Collapse a hydrogen only when it is an unambiguous ordinary explicit hydrogen:

- exactly one incident localized bond;
- single localized bond;
- non-hydrogen partner;
- no isotope label, charge, spin, or other non-default atom state;
- no participation in dative, aromatic, multicenter, noncovalent, or stereo
  relations.

Remove the hydrogen and bond and increment the partner's implicit-hydrogen
count. Preserve D/T, hydrides/protons, radicals, H2, relation participants, and
any hydrogen whose information could not be represented after collapse.
Reapplying the transformer is a no-op.

Both types implement `Transformer`. The pair round-trips molecules that lie in
the source form of the first transformation; no stronger universal roundtrip
claim is implied.

Verification must cover per-direction behavior, idempotence, field preservation,
relation preservation, and roundtrips over the admitted subset.

## Validator completion

### Spin invariants

`SpinInvariantsValidator` is currently a stub. For every entity carrying
`SpinStateAst`, check literal unpaired-electron count and multiplicity using the
compatibility rule in `umol_chem::spin::SpinState`. Return
`Underdetermined` when the required values are not literal, and a specific
contradiction for incompatible literal pairs.

The molecule-wide path covers atoms, aromatic systems, and multicenter bonds.
`validate_atom` applies the same rule to a standalone atom.

### Constraint integrity

`ConstraintValidator` is currently a stub. Its implementation, the split between incidence, ring,
relational, and molecule-scope evaluation, its contradiction hierarchy, and the resolver precondition
checks belong to the same work unit as aromaticity and stereo consistency. They are specified and
planned in [doc 171](171-aromaticity-inconsistency-policy-2026-07-29.md#validator-ownership).

This document retains no parallel constraint-validator implementation plan. Completion of doc 171
satisfies the constraint-integrity portion of this worklist, including the explicit deferral of
multi-donor dative semantics to doc 117.

### Aromaticity conformance

The completion of `AromaticityConformanceValidator` is planned together with
aromatic resolution and projection consistency in
[doc 171](171-aromaticity-inconsistency-policy-2026-07-29.md).

### Connectivity model

Wire `ConnectivityModel` (`umol-ast/src/ast/validate/connectivity.rs`) into
`ChemistryModel` alongside the valence, aromaticity, and stereo models, and run
its check in the topology phase ahead of valence, per the phase order in doc
054.

- Connectedness is model-dependent and belongs with the other model components
  rather than beside them: whether a dative adduct such as H3N→BF3 is one
  structure, and whether a hydrogen-bonded dimer is, are choices a caller makes.
- The per-relation switches are the substance of that choice. Keep them
  independent; do not collapse them into a single flag.
- A reaction side routinely has several components, so the reaction paths must
  select a permissive setting explicitly rather than inheriting a molecule
  default.
- Decide whether the existing permissive defaults remain the defaults once the
  model is reachable from the chemistry model, and record the decision.

### Remaining entity checks

Audit the current validators before introducing more validator types. In
particular, determine which of the following are not already covered by
`EntityStructureValidator`, `ValenceInvariantsValidator`, and
`ValenceConformanceValidator`:

- implicit-hydrogen and total-hydrogen constraint/state agreement;
- localized- and dative-bond charge/spin consistency;
- multicenter charge, spin, and electron consistency;
- noncovalent and other overlay uniqueness;
- numerical ranges required by the DSL specification.

Add a separate validator only when it represents a distinct integrity,
invariant, or conformance operation. Do not recreate the stale file-by-file
validator list from doc 086.

## Composite behavior

- Preserve the tier order: integrity, invariants, conformance.
- Structural checks run before chemistry-dependent checks.
- Validators never mutate or invoke resolvers.
- Resolution materializes intermediate state between valence, aromaticity,
  bond, multicenter, and stereo stages as required by their contracts.
- Operation-specific errors identify the failed rule and entity rather than
  returning an empty contradiction enum.

## Completion criteria

- The hydrogen transformer pair is public, idempotent, and lossless on its
  documented domain.
- `ConnectivityModel` is a member of `ChemistryModel` and runs in the topology
  phase.
- `ConstraintValidator` and `SpinInvariantsValidator` contain no stub path.
- The composite validator has property tests for determined,
  underdetermined, and contradictory outcomes and passes after successful
  resolution.
