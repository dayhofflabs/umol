# SSSR Considered Harmful?

## Question

I just read a post by OpenEye, the cheminformatics software maker, calling the SSSR alg "harmful", Dijkstra style, mostly because it's not unique and dependent on the atom ordering. They proudly proclaim that OEChem is 100% SSSR free.  Only grass fed and free from preservatives, too, I'm sure. Now, the OpenEye guys are not Dijkstra, presumably not even Bellman-Ford, but I'd like to understand their point. First, isn't non uniqueness of a cycle basis always a problem in a sufficiently symmetric case (they specifically mention cubane). Second, what alternative algorithms can be used for ring perception, specifically for downstream aromatic system assignment?

## Response

Good question, and the OpenEye critique (I believe originally articulated by Roger Sayle) does have real substance beneath the marketing.

**On non-uniqueness:** Yes, you're right — this is intrinsic to minimum cycle bases (MCBs), not an artifact of any particular algorithm. Cubane's cycle space has dimension 5 (|E| - |V| + 1 = 12 - 8 + 1 = 5), but by symmetry all 6 square faces are equivalent. Any MCB must pick 5 of 6, so no canonical choice exists without breaking symmetry. The SSSR *is* an MCB, so the criticism is really that MCBs are the wrong abstraction for chemistry — which is fair.

**The actual problem for chemistry:** Downstream tasks like aromaticity detection need *all* relevant rings, not a minimal independent set. If your SSSR of naphthalene happens to contain the two 6-rings, great — but it's equally valid to pick one 6-ring and the 10-ring envelope. An aromaticity detector built on SSSR output is fragile.

**Alternatives, in increasing order of usefulness:**

- **Essential rings** — rings that appear in *every* MCB. Unique but incomplete (cubane has none).
- **Relevant cycles** (Vismara, 1997) — the union of all MCBs. Unique, chemically much more useful, but can blow up combinatorially in pathological graphs (though real molecules are rarely pathological).
- **Smallest ring at each bond/atom** — pragmatic: for each bond, find the smallest enclosing ring. Not a cycle basis but gives you exactly what you need for local ring membership queries.
- **For aromaticity specifically:** skip ring enumeration entirely. Extract the subgraph of potentially aromatic atoms (sp2-hybridized, appropriate lone pairs on heteroatoms), find connected components, then detect simple cycles within each component and check Hückel (4n+2 π-electrons). This decouples aromaticity from the ring perception problem. You only need cycle detection in small subgraphs, not a global ring basis.

The last approach is essentially what OEChem does (and what RDKit mostly does too, despite nominally computing SSSR). The insight is that aromaticity is a *local* property of π-systems, not a global graph property, so you never need a global cycle basis.

For your `umol` work — if you're implementing aromaticity, I'd go straight for the π-subgraph approach. Connected components you already have; cycle detection in small planar subgraphs is cheap.

## Reply

Can you list the applications of cycle basis detection? Aromaticity, number of rings, ring size queries (which is kind of tautological since one is able to create these queries only because one can detect the rings and ring sizes. But maybe I don't understand the genius that is QSAR. What else?

## Response

Honest accounting:

1. **Aromaticity** — the big one, but as discussed, better solved without a global cycle basis.

2. **Ring-based descriptors for QSAR/fingerprints** — ring count, ring size distribution, number of aromatic/aliphatic rings, ring fusion patterns. As you note, somewhat circular (pun intended). These are features because they're computable, not because anyone derived them from first principles.

3. **Smallest enclosing ring size per atom/bond** — needed for force field atom typing (e.g., sp3 carbon in a 3-ring vs 6-ring has different angle parameters). Again, doesn't need a full cycle basis — local shortest-path suffices.

4. **Ring membership for SMILES canonicalization** — you need to decide where to open rings and place ring-closure digits. Requires identifying ring bonds but not a basis per se; a spanning tree suffices.

5. **Scaffold decomposition** (Bemis-Murcko and friends) — ring systems and linkers. Needs connected ring systems, not individual cycle enumeration.

6. **Macrocycle detection** — relevant for conformer generation (macrocycles need special sampling). Just need to know if any ring exceeds some size threshold.

7. **Reaction mapping / bond change detection** — ring opening/closing events. Comparing ring membership before and after, not really a basis problem.

So the pattern is: almost every *real* downstream task needs some local or aggregate ring information, but virtually none of them actually require a minimum cycle basis. They need things like "is this bond in a ring?", "what's the smallest ring containing this atom?", or "what are the connected ring systems?" — all answerable with simpler primitives (spanning trees, BFS shortest paths, biconnected components).

The SSSR was a solution looking for a problem. The chemically meaningful questions were always more specific and simpler than "give me a minimum cycle basis."
