## Purpose and boundaries

Identify the remaining work for 0.10 before expanding its implementation scope. The
current branch already contains substantial changes from 236 and 181. External
requests and contributions receive the same semantic, interface, nomenclature,
correctness, testing, and performance scrutiny as work developed in this repository.
Passing CI and contributor-reported benchmarks do not establish acceptance.

This record collects release decisions and unresolved questions. The owning
discussion documents retain their implementation scope and status; inclusion here
does not imply that their outstanding work has been implemented.

## Open GitHub issues

### Issue 30 — localized valence specification

[Issue 30](https://github.com/dayhofflabs/umol/issues/30) identifies a specification
error. Localized valence includes every incident localized bond, including bonds
to explicit hydrogen atoms. The exclusion of hydrogen in the DSL specification
and nomenclature guide is wrong. Correct those descriptions and preserve the
implemented semantics; this is not a request to redefine valence.

### Issue 31 — aromatic systems and reaction applicability

[Issue 31](https://github.com/dayhofflabs/umol/issues/31) needs review and a design
discussion. The reported application deletes an internal localized bond while
retaining the host aromatic system. The current dangling checks cover deleted
atoms and their incident entities; aromatic systems store atoms, without explicit
bond participants.

The preferred direction for discussion is to strengthen the dangling-condition
checks. The broader alternative is to include bonds explicitly in aromatic systems.
Neither is accepted for implementation yet. The narrow approach must state which
bonds an aromatic system depends on and check the actual host context, including
systems absent from the reaction lhs. It must distinguish internal changes from
unrelated exocyclic or inter-system bond changes. Bond deletion, addition, and
order changes need separate consideration rather than an automatic common policy.

### Issue 6 — explicit and implicit hydrogen

[Issue 6](https://github.com/dayhofflabs/umol/issues/6) requests an explicit
hydrogen-representation conversion. The hydrogen operations in 166 address this
need. Canonical comparison must continue to preserve the represented distinction;
this issue does not justify silently folding hydrogen during canonicalization.

## Contributed pull requests

### PR 28 — coset-space registry

[PR 28](https://github.com/dayhofflabs/umol/pull/28) replaces the shared mutex and
map with one static OnceLock per supported ClassKey. Review the complete domain
mapping, uniqueness of the issued space reference, concurrent initialization,
panic behavior, and tests. The reported throughput improvements are evidence to
assess, not an acceptance decision. The change remains unaccepted pending review.

### PR 29 — canonical-search pruning

[PR 29](https://github.com/dayhofflabs/umol/pull/29) extends pruning to reaction
spans and to a subset of full-level searches. Review the claim that pruning
preserves the selected canonical value and remapping, the generator filters, and
coverage beyond identity spans. Its reported 6–13% regressions on several stereo
cases need an explicit disposition alongside the reported scaling improvements.

Atom #T constraints and all bond constraints, including #C, disable the proposed
full-level pruning. Falling back to exhaustive search is a conservative behavior,
but separating support for these constraints into other work is not an accepted
requirement. Analyze whether their frame handling can be covered coherently here.

The contributed discussion document numbered 231 can be renumbered when integrating
the contribution; that collision is not a substantive objection. Its proposed
Completed status does not substitute for review. The PR remains unaccepted.

## Downstream wishlist

### Relative count updates

The concrete requirement is to set a product count to the matched host count plus
a constant, notably implicit hydrogen count and charge. A rule leaving the lhs
count open should not need separate handwritten rules for every permitted literal.

This does not establish a requirement for the full variable facility in
[115](115-variable-facility-2026-06-16.md). First determine whether a bounded
field-relative update can meet the use case. A convenience operation evaluated
while building a rule is different from an offset evaluated against a later host
match. Likewise, translating a set of allowed counts does not retain the required
relationship between each matched value and its result.

If offsets are stored in reusable reactions, their consequences for application,
inversion, composition, representation, and serialization must be understood before
accepting the change. No syntax, public type, implementation, or release inclusion
is settled here. Avoid expanding this into general variable binding by default.

### Other requests

Recursive group subpatterns ([193](193-subpattern-constraints-2026-08-09.md))
are outside 0.10 scope. The complaint about numeric variables parsing without
producing the intended matches is too vague to justify implementing the scheduled
variable facility. It needs a concrete contract before any diagnostic change is
scheduled. Existing hydrogen-representation work belongs to 166; SMILES export
already exists and is a downstream version-update matter.
