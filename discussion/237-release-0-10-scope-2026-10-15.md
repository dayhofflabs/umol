## Unresolved SMILES ingestion (completed)

Rust already exposes parsing and TableIR-to-graph-IR conversion separately, but
Python's Molecule.from_smiles previously always resolved. The new convenience
functions are ingest::ingest_smiles_unresolved(input) and
ingest::ingest_smiles_unresolved_with(input, io_config), returning Result<Molecule,
SmilesInputError>. They apply the existing format-owned defaults and convert to
graph IR without invoking Resolver. Undetermined fields and raised constraints
are preserved; failures are Syntax or ModelConversion.

Python Molecule.from_smiles has the keyword-only resolve=True argument.
resolve=False delegates to ingest::ingest_smiles_unresolved_with; the default
continues to use ingest::ingest_smiles_with. io_config applies in both modes;
chemistry_model and resolve_config are ignored with resolve=False. The binding
does not construct a default chemistry model or resolution config on that path.
The two Rust operations share one Python constructor for the same input format.

Verification covers undetermined and explicit fields, aromatic assertions,
tetrahedral stereo, custom IO syntax, parsing/conversion failures, and unchanged
resolved defaults. No parser, conversion, or resolver algorithm changes are needed.

Completed 2026-10-20: 265 Rust ingestion tests, 5 Rust binding tests, and 323 Python
molecule/resolution/SMILES-export tests passed after rebuilding the extension.
Workspace Clippy passed with all targets, all features, and warnings denied;
formatting passed with the CI-pinned nightly formatter. No benchmarks were needed
for these wrappers around existing operations.

### Reaction SMILES — 2026-10-26

The same choice now applies to reactions. Rust adds
ingest::ingest_reaction_smiles_unresolved and
ingest::ingest_reaction_smiles_unresolved_with, returning Result<Reaction,
ReactionSmilesInputError>. Both sides are raised without resolution and assembled
using the existing atom-map correspondence and Reaction::from_sides. Format-owned
values, constraints, and raised overlays are preserved. The product is reindexed
into the lhs-anchored reaction frame.

Python Reaction.from_reaction_smiles adds keyword-only resolve=True. False selects
the new Rust path, with io_config applying and chemistry_model/resolve_config
ignored, as for Molecule.from_smiles. Agent rejection, ambiguous-map rejection,
one-sided labels, and side-qualified conversion errors keep their existing semantics.
Resolved and unresolved ingestion share the map checks and reaction construction.

Verification: 281 Rust ingestion tests and the full Python suite (3,010 passed,
2 skipped) passed. Workspace Clippy passed with all targets, all features, and
warnings denied; formatting passed with the CI-pinned nightly formatter.
The initial all-feature workspace run exposed an invalid-removal generator case:
when a stereo-bond ligand was adjacent to both endpoints, the generator protected
only the first connecting bond and could remove the bond required by the ligand
frame. The generator now protects both connections, as its documented domain
requires. Existing compaction properties also require successful publication,
instead of accepting two matching errors. The composition law and production
removal semantics are unchanged. All four compaction properties passed with
1,024 cases each, including replay of the failing seed.
The final all-feature workspace run passed: 39,797 tests, 10 ignored; workspace
Clippy remained clean.

## Downstream wishlist

### Relative count updates

The concrete requirement is to set a product count to the matched host count plus
a constant, notably implicit hydrogen count and charge. A rule leaving the lhs
count open should not need separate handwritten rules for every permitted literal.

This does not establish a requirement for the full variable facility in
[115](115-variable-facility-2026-06-16.md). First determine whether a bounded
field-relative update can meet the use case. A convenience operation evaluated
while building a rule is different from an offset evaluated against a later host
match. Likewise, translating a set of allowed counts does not retain the required
relationship between each matched value and its result.

If offsets are stored in reusable reactions, their consequences for application,
inversion, composition, representation, and serialization must be understood before
accepting the change. No syntax, public type, implementation, or release inclusion
is settled here. Avoid expanding this into general variable binding by default.

### Other requests

Recursive group subpatterns ([193](193-subpattern-constraints-2026-08-09.md))
are outside 0.10 scope. The complaint about numeric variables parsing without
producing the intended matches is too vague to justify implementing the scheduled
variable facility. It needs a concrete contract before any diagnostic change is
scheduled. Existing hydrogen-representation work belongs to 166; SMILES export
already exists and is a downstream version-update matter.
