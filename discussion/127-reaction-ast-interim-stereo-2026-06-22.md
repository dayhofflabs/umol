# 127 — Reaction AST: interim stereo correspondence and partial maps

Status: Active
Date: 2026-06-22

## Scope

A *small* set of fixes to `umol-ast::ast::reaction`, the minimum the fingerprint
work (doc 126) needs, **not** the full reaction redesign. The full treatment —
rename to `ReactionAst` (homoiconic concrete-reaction *and* rule), non-injective
templates (RDKit reaction SMARTS), full stereo/overlay rewrite semantics, transition
states — remains a separate, larger task (its own doc later). Here we assume
**SMIRKS semantics**: a partial atom map, injective in both directions.

`ReactionRuleAst`/`Assignment` have one consumer: `apply_rule`, the DPO rewrite in
`ast/molecule/rewrite.rs`. It is implemented but currently **uncalled and untested**
(no callers, no test module). The old `atom_map` listed only the K interface, with
create/destroy inferred by *absence* from the L/R atom sets. The partial-map change
is behavior-preserving there by construction: `apply_rule` derives the K maps from
the `(Some, Some)` entries and keeps the absence-inference, so when every entry was
`Some` (the only prior possibility) `k_pairs` equals the old total `atom_map`;
explicit `(Some, None)`/`(None, Some)` entries are currently redundant with that
logic. The stereo correspondences are not yet read by `apply_rule` — the
product-coset rewrite is deferred (below).

## Decisions

### i. Stereo entities in `Assignment`

`Assignment` (the L→target match produced by substructure matching) covers every
entity type except stereo. Add, mirroring the same-shape `SubPatternAnchor`
(`constraint/molecule.rs`):

```rust
pub stereo_atoms: Vec<(StereoAtomId, StereoAtomId)>,
pub stereo_bonds: Vec<(StereoBondId, StereoBondId)>,
```

### ii. Partial atom map

`ReactionRuleAst.atom_map`: `Vec<(AtomId, AtomId)>` → `Vec<(Option<AtomId>,
Option<AtomId>)>`. `(Some, None)` = destroyed; `(None, Some)` = created;
`(Some, Some)` = preserved interface (K). No existing general correspondence type is
reusable; `SubPatternAnchor` is a same-shape precedent for the *match* side only.

### iii. Stereo correspondence for stereo elements

The atom map cannot track **virtual ligands** (implicit H, lone pair): doc 101 §4
models them as *ports with no far-side atom* — frame positions, not atoms. So a
stereo-element correspondence is needed in addition to the atom map.

This matches the molecular-graph-grammar literature. MØD (Andersen, Flamm, Merkle &
Stadler 2017, *Chemical Graph Transformation with Stereo-Information*) uses the
**ordered list method**: an order on a vertex's incident edges, with **permutation
groups** giving equivalence classes of orderings = the same local embedding. That is
exactly umol's model — an ordered `StereoLigand` frame with a coset under the
geometry's group (`StereoKind::act` / `involution` already exist). So the reaction
layer only has to express how the ordered frame maps L→R.

The reaction behaviors are coset operations on that ordered frame:
- `create` / `destroy` — presence (R-only / L-only), via `Option` on each side.
- `preserve` / `swap` / `mirror` / `apply` — a **permutation of the ordered frame**
  L→R, applied to the coset via the existing algebra: preserve = identity, swap =
  transposition, mirror = the geometry's `involution()`, apply = general. Ligand
  *kinds* at each position live in `lhs`/`rhs`, so a permutation over frame
  positions is sufficient (it also covers a virtual→real change like protonation).

Shape (separate types per stereo kind, generated by a macro to avoid duplication):

```rust
pub struct StereoAtomCorrespondence {
    pub lhs: Option<StereoAtomId>,   // None => created on R
    pub rhs: Option<StereoAtomId>,   // None => destroyed from L
    pub frame: Option<Permutation>,  // both present: L frame → R frame; None == preserve
}
// likewise StereoBondCorrespondence over StereoBondId
```

`ReactionRuleAst` gains `stereo_atoms: Vec<StereoAtomCorrespondence>` and
`stereo_bonds: Vec<StereoBondCorrespondence>`.

## Settled choices (this round)

1. `frame` is a `Permutation` (reuses `umol-perm`; drives the coset transform via
   `act`/`involution`).
2. Separate types per stereo kind, generated by a macro (one definition).
3. Transformations are *included* (the `frame` field), but only the `swap`
   constructor lands now — `mirror`/`apply` later. Constructors: `preserve`,
   `create`, `destroy`, `swap`. Scope is **tetrahedral and cis/trans** stereo only.
4. Captured here (doc 127).

## Deferred

- `mirror`/`apply` constructors and non-tetrahedral / non-cis-trans geometries.
- Non-injective reaction templates (RDKit reaction SMARTS) and the full
  `reaction.rs` redesign (rename → `ReactionAst`, overlay rewrite semantics).
- The reaction stereo-rewrite *engine* (computing product cosets when a rule fires,
  transition states) — at that point read MØD 2017 and StereoMolGraph
  (`stereodescriptors.py`) in full; flagged in doc 101 §3.

## Follow-ups (noted, not yet scoped)

Raised after the interim landing; the current `reaction.rs` is sufficient to proceed
with the fingerprint work (doc 126), so these are recorded, not acted on.

### i. `apply_rule` ignores stereo entirely

`apply_rule` (`ast/molecule/rewrite.rs`) has phases for atoms, bonds, and all four
overlay families (dative / aromatic / multicenter / noncovalent) but **none for
stereo**. It never reads `ReactionRuleAst.stereo_atoms`/`stereo_bonds` nor
`Assignment.stereo_atoms`/`stereo_bonds`, so the stereo correspondences added this
round are inert in the rewrite — there is no create / destroy / frame-transform of
stereo elements when a rule fires. Wiring this in is the deferred product-coset
rewrite engine.

### ii. Three near-synonyms for "mapping"

We now name very similar concepts three different ways:
- **map** — `atom_map: Vec<(Option<AtomId>, Option<AtomId>)>`: a partial,
  bi-injective correspondence (create / destroy via `None`).
- **assignment** — `Assignment`: the L→target (G) match from substructure matching,
  a total per-entity 1:1 injection.
- **correspondence** — `Stereo{Atom,Bond}Correspondence`: a partial bi-injective
  mapping *plus* a transformation (`frame: Option<Permutation>`).
- (`SubPatternAnchor` in `constraint/molecule.rs` is a fourth, same-shape precedent.)

These are points on one axis — total 1:1 / partial bi-injective / with-transform —
and should share one base term with qualifiers rather than three unrelated words.
Unify the vocabulary before the full redesign.

### iii. Vecs of correspondences vs. the three-part relational model

Question whether `Vec<…Correspondence>` is the right container at all. The relational
model has three parts: **underlying topology, overlays, and properties**. Pure DPO
(L ← K → R) covers only the *topology*. So the reaction representation should be DPO
on the topology **plus the existing edit / transaction infrastructure** (`edit.rs`
`Edit`/`Undo`, `molecule::transact::Transaction`) for overlay creation / destruction
and property edits — not parallel per-family vecs of correspondences reinventing what
`Edit`/`Transaction` already express. This reframes the full `reaction.rs` redesign:
a rule = a topological DPO span + a transaction over overlays and properties.
