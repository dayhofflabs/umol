## Purpose

This document scopes atom-to-atom mapping between two molecular sides and
sketches a native umol design. The immediate use is constructing `Reaction`
values when the sides are known but their atom correspondence is not.

The operation should be exact with respect to a small, published structural
objective and should enumerate every optimal labeled correspondence. It should
not claim to recover an unobserved reaction mechanism. External atom mappers,
learned models, and mathematical-programming solvers are useful development
oracles and incumbent generators, but are not intended runtime dependencies.

This is the design and implementation record for the first exact structural
atom-mapping operation.

## Scope

The proposed scope covers:

- `Molecule` lhs and rhs inputs, including lattice-valued element forms and
  disconnected collections represented as one molecule on each side;
- unbalanced sides through a partial atom bijection rather than a requirement
  that every input atom have a partner;
- one fixed representation-level objective: maximize element-compatible
  matched atoms, then minimize unit localized-bond additions, deletions, and
  order modifications;
- enumeration of all optimal labeled atom correspondences, including distinct
  mappings created by molecular and component symmetries;
- a chemistry-independent `graph_edit` search in `umol-graph-core` over two
  simple `Graph` values with caller-supplied node-compatibility and
  edge-equivalence closures;
- a molecule operation in `umol-graph-ir` that supplies
  `ElementForm::is_compatible` and order-form equivalence to that kernel;
- checked lifting of a selected atom correspondence into a
  `MoleculeCorrespondence` and `Reaction`;
- exact branch-and-bound search, a definition-level exhaustive baseline, and
  two-pass visitor delivery;
- initial controlled comparison against the local Rhea RXNMapper results;
- correctness fixtures, property laws, adversarial symmetry cases, corpus
  comparisons, and performance measurements needed to validate the
  implementation.

The scope does not include:

- predicting, ranking, or encoding reaction mechanisms;
- learning reaction-class, active-bond, or bond-breaking preferences;
- treating one external mapper as ground truth;
- silently selecting one representative from a symmetric optimum class;
- canonical reaction-template extraction or reaction classification;
- format parsing or standardization policy;
- atom-field, overlay, stereo, reaction-class, or mechanism-derived objective
  terms;
- objective levels, weights, anchors, search budgets, or a configuration
  object;
- symmetry pruning, an additional optimized exact backend, or an external
  runtime solver;
- a Python API design beyond preserving the Rust semantics later.

## Central semantic limit

An atom map is additional information, not generally a function of the two
structural formulas alone. Several maps can conserve the same number and kinds
of bonds while implying different condensed reaction graphs. The chemically
preferred map can depend on the actual mechanism, including information absent
from both sides.

This is not only a pathological symmetry issue. The recent partial-map analysis
by González Laffitte, Phan, and Stadler states the underlying difficulty
directly: a chemically correct map is determined by the ground-truth mechanism,
while minimal chemical distance, least nuclear motion, and common-subgraph
criteria are approximations. Their positive result starts after a suitable
partial reaction-center map is known: stable completions are constrained graph
isomorphisms and are equivalent up to the induced transition-state graph
([WABI 2025 paper](https://doi.org/10.4230/LIPIcs.WABI.2025.12),
[2026 journal version](https://doi.org/10.1186/s13015-026-00300-5)).

The production contract must therefore say:

> Return all atom correspondences that are globally optimal under the stated
> structure-only objective.

It must not say:

> Return the reaction's true atom map.

Mechanism knowledge may be compared after the fact or supplied later as an
explicit hard partial correspondence. It must not be hidden in element weights,
reaction-class tables, output order, or a silent tie-break.

## Existing umol substrate

The repository already has most of the representation machinery needed by the
operation:

- `Correspondence<AtomId>` is a sized partial bijection with checked
  construction, inversion, composition, and matched/unmatched reads.
- `MoleculeCorrespondence::induce(lhs, rhs, atoms)` checks the supplied molecule
  pair and derives bonds and all overlay-family correspondences from the atom
  relation.
- `Reaction::from_sides(lhs, rhs, atoms)` induces the complete correspondence
  and derives the lhs-anchored deltas of the central reaction representation.
- graph-core has explicit algorithms for common induced and common edge
  subgraphs, seeded MCES, subgraph-isomorphism enumeration, maximum matching,
  and exact automorphism discovery through vendored nauty.
- maximum common-subgraph calls eagerly return all maxima. Other graph
  enumerators establish the repository's visitor plus eager-counterpart
  convention and `ControlFlow` early termination.
- aggregate molecule canonicalization represents atom, bond, and overlay
  incidence exactly. It is a stronger symmetry substrate than local
  Weisfeiler--Lehman ranks.

The missing capability is not a map carrier. It is the operation that searches
the space of compatible partial bijections, proves the optimum, and visits all
assignments at that optimum.

### Why current MCES is not the complete operation

The current maximum common edge-subgraph search is a useful ingredient and a
small-case oracle, but atom mapping has a different contract:

- mapping must first conserve as many compatible atoms as possible; an MCES can
  omit isolated or inconvenient atoms without penalty;
- a mapped bond whose order or inherent form changes is a modification, not an
  unmapped atom pair;
- unbalanced sides require explicit unmatched atoms while retaining all
  possible conserved atoms;
- the complete score is lexicographic rather than only maximum common-edge
  cardinality;
- every optimum must lift successfully to the aggregate molecule pair;
- exact symmetry handling must preserve all labeled output maps.

Forcing these semantics through the existing `McesAlgorithm` API would obscure
both contracts. The fixed optimization is instead a distinct, reusable
`graph_edit` problem in graph-core; molecule-specific compatibility and result
lifting remain in graph-IR.

## Local atom-mapper evidence

The inspected repository at `/Users/dr/Dayhoff/atom-mappers` was last committed
in December 2024. Its data directory contains 15,954 Rhea reaction rows,
14,430 RXNMapper outputs, and 15,827 Indigo outputs.

The two output files are not a controlled head-to-head experiment:

- RXNMapper input was standardized and uncharged and was filtered with a
  maximum token length of 512;
- Indigo received the original reaction SMILES, used
  `reaction.automap("discard")`, and had a 60-second timeout;
- the output sides therefore often differ in protonation, charge, component
  form, or retained records before map quality is considered.

A read-only audit of the exported map labels found:

| Parsed output rows | 14,430 | 15,827 |

The repeated Indigo labels mean those exported rows do not describe a partial

claim about every Indigo mode or version.

Only 245 common records had exactly equal unmapped side signatures after the
different preprocessing. Of those, only 177 had partial-bijection-shaped output
from both tools. The sample contains both different-score disagreements and
equal-score, non-equivalent condensed graphs. It is too small and confounded to
support a mapper-accuracy ranking, but it is sufficient to reject exact map
label equality as an evaluation method.

The downstream `atom-mappers` combined-graph canonicalizer also needs care as
an oracle. It refines local ranks and resolves a remaining tie by choosing the
first tied node. That produces a deterministic serialization for one input
order, but it is not exact automorphism handling. Its reduced graph retains
atoms around bond-order changes and can omit atom-only changes. The original
mapped reactions are therefore the useful evidence; the reduced canonical
templates are not authoritative map equivalence classes.

### First controlled RXNMapper comparison

The first controlled comparison uses each saved RXNMapper output as its own
molecular frame. The mapped SMILES is parsed once through `umol-io`, both sides
are raised to graph IR, its map labels are read as one candidate
`Correspondence<AtomId>`, and the exact mapper operates on those same molecule
values and atom ids. This deliberately isolates mapping from preprocessing. It
does not yet compare RXNMapper and Indigo on a common standardized Rhea frame.

The saved result is a reproducible RXNMapper 0.4.0 baseline. The project pins
`rxnmapper==0.4.0`, and `run.sh` records `--standardize`, `--mapper rxnmapper`,
and `--max-length 512`. Exactly 14,430 of the 15,954 source rows satisfy that
length cap, and all 14,430 appear in the output. The missing 1,524 records are
therefore filter exclusions, not recorded mapper failures. The wrapper stores
only `mapped_rxn`; it discards RXNMapper's confidence value.

A complete candidate-only pass gave:

| Observation | Count |
| --- | ---: |
| Saved RXNMapper outputs | 14,430 |
| Parsed by `umol-io` | 14,430 |
| Raised to graph IR on both sides | 14,429 |
| Valid element-compatible partial bijections | 14,429 |
| Candidates with maximum possible compatible-atom count | 14,336 |
| Candidates below that atom-count optimum | 93 |

The one raise failure is Rhea `Rh_22216`, whose product has contradictory
cis/trans markers at one atom. It is an umol boundary/raise failure, not an
invalid RXNMapper correspondence. Every atom-count deficit contains at least
one wildcard: 21 are short by one atom, 70 by two atoms, and two by three
atoms. No concrete-element candidate is below the primary objective. This is a
specific interaction between RXNMapper's handling of atomic-number-zero atoms
and umol's element lattice, under which a wildcard is genuinely undetermined
and compatible whenever the element-form meet exists.

The saved output cannot be scored directly against the unstandardized source
SMILES. Among the 14,417 records for which both forms raise through the current
umol boundary, only 4,589 retain the same lhs/rhs atom counts, and only 4,583
retain both the same atom and localized-bond counts. Most differences are the
expected explicit-hydrogen and protonation consequences of the recorded
uncharging pass, but they are enough to make raw atom indices and raw edit
scores incomparable.

The initial exact slice selected the 1,500 outputs with the fewest saved map
labels. One wildcard-rich record, `Rh_12044`, exceeded both the 0.5-second
slice budget and a separate 10-second attempt. The other 1,499 records, with at
most 15 atoms on either raised side, were proved exactly:

| Candidate result under the fixed objective | Count |
| --- | ---: |
| Globally optimal | 1,360 |
| Same maximum atom count, one extra bond edit | 69 |
| Same maximum atom count, two extra bond edits | 47 |
| Same maximum atom count, three to eight extra bond edits | 22 |
| Two fewer matched atoms | 1 |

Thus 90.7% of this deliberately small, tractable slice attains the exact fixed
objective. This is not a corpus-wide accuracy estimate. A deterministic random
sample of 1,000 records with a 200-millisecond per-record budget proved only
275 cases. Coverage fell from 46/46 below ten saved map labels and 152/162 from
ten through nineteen, to 37/141 from twenty through twenty-nine and 20/101 from
thirty through thirty-nine. Only 20 cases at forty labels or above were proved.
The current branch-and-bound implementation is therefore adequate for the
small controlled comparison but not for exact evaluation of the Rhea corpus.

The strict-score disagreements must not automatically be reported as mapper
errors. RXNMapper 0.4.0 greedily consumes transformer-attention pairs under an
element mask and boosts adjacent pairs; it does not optimize or certify umol's
global edit objective. Conversely, umol's first objective intentionally
ignores atom attributes other than element and can obtain a lower edit score
by permuting same-element atoms in a chemically unintuitive way. Curated review
of representative cases distinguishes both outcomes:

- `Rh_20309` maps four oxygen atoms across peroxide, water, and dioxygen.
  RXNMapper reports confidence 0.16973 and costs three edits. The two-edit map
  `[OH:1][OH:2].[OH:3][OH:4]>>[OH2:1].[OH2:2].[O:3]=[O:4]` is chemically
  correct.
- `Rh_63116` has RXNMapper confidence 0.90832 but still costs four edits. The
  two-edit minimum is likely the correct map. Expressed in the original charged
  Rhea frame, that atom identity is
  `[O:1]=[N:2][O:3][O-:4]>>[O:1]=[N+:2]([O-:3])[O-:4]`. High model confidence
  therefore does not imply optimality under the structural objective or settle
  the chemical judgment.
- `Rh_34527` costs ten edits under the saved map and two under a topology-only
  optimum that exchanges carbon identities across the chiral center and side
  chain. The lower score is not by itself evidence of a more plausible
  mechanism.
- `Rh_12116`, `*.[H][H]>>[H]*[H]`, costs three edits under the intuitive
  wildcard-to-wildcard map and one when lattice compatibility permits a
  hydrogen/wildcard exchange. Curated review identifies the intuitive map as
  correct, so the current minimum is wrong despite being the exact optimum of
  the published first objective.

These results validate RXNMapper as a useful chemically informed comparator
and reject both one-sided interpretations: RXNMapper disagreement can expose a
wrong learned map, while a lower structural score can expose a weakness in the
fixed objective rather than a better chemical map. `Rh_12116` is specifically
evidence that lattice compatibility is a sound feasibility relation but does
not make every compatible atom substitution equally preferable. An eventual
node-substitution cost or element-form preservation objective could prefer
wildcard-to-wildcard and literal-to-literal pairs without making wildcards
incompatible, but that would be a new mapping objective rather than a repair to
the exact search. The next comparison needs induced reaction-span/CGR
equivalence and further curated mechanism evidence before choosing such an
extension.

### How to use the corpus

The saved results should be treated as approximate oracles with four separate
questions:

1. Does the export satisfy the partial-bijection and atom-compatibility
   contract?
2. What structural score does it attain after both inputs are converted through
   the same boundary and standardization path?
3. Is its induced reaction span or condensed reaction graph equivalent to one
   of the exact optima, independent of atom numbering?
4. If it disagrees, is the disagreement an input symmetry, a distinct
   equal-score reaction graph, a strictly worse structural score, or an
   externally known mechanism preference?

RXNMapper and Indigo may seed a development solver's incumbent after their
candidate has been checked. A valid candidate score is safe pruning evidence;
the external mapping itself must never become a hard constraint or runtime
requirement.

### LocalMapper is paper-only evidence

LocalMapper is not a candidate implementation, runtime dependency, development
oracle, or benchmark executable for this work. Its current repository license
is CC BY-NC-SA 4.0, its README excludes commercial use without prior written
approval, and the authors expressly request permission for such use. umol is an
open-source project distributed under Apache-2.0 or MIT, not a commercial
product. Those licenses deliberately preserve commercial use for downstream
users, however, so noncommercial-only material cannot enter umol's distributed
code, model, or data chain without narrowing the rights that umol grants them.

The exclusion is also a project-policy decision rather than an attempt to find
the narrowest legally permissible interaction. The repository's expressed
permission posture is incompatible with the open collaboration boundary wanted
for umol. There is therefore no need to resolve the legal effect of older
repository states or of the request separately from the license: umol will not
inspect, run, vendor, translate, or derive from the LocalMapper repository,
model weights, or generated artifacts.

The published paper remains useful research evidence. Its mapper learns an
atom-pair probability matrix from chemist-labeled reactions using local message
passing and cross-reaction attention, then extracts one mapping by consuming
high-probability pairs. This does not prove a structural optimum, enumerate
degenerate optima, or supply exact symmetry semantics, so it does not address
the central algorithmic contract here.

Three paper-level ideas remain relevant without using the implementation:

- learned pair probabilities can be understood abstractly as incumbent or
  value-ordering heuristics for an exact search, although umol does not need a
  learned heuristic initially;
- novelty against a chemist-verified reaction-template library is a useful
  way to direct human review and may inform later template-library curation;
- evaluating mappings through the induced condensed reaction graph avoids
  treating equivalent raw map labels as disagreements.

None is unique enough to justify contact with the code. The first belongs to
general learned matching, the second to an evidence-guided curation workflow,
and the third is already standard evaluation practice in the cited literature.

The notable work since the local experiment is the all-maximum-clique

The label "chemistry-specific" covers three distinct uses of chemical
information:

- a hard compatibility or mechanism constraint removes correspondences from
  the feasible set;
- an additional chemical score ranks the feasible correspondences under a
  different objective;
- an incumbent or branch-ordering hint changes only the execution of an exact
  solver, provided it never removes a candidate and the solver still proves
  and enumerates the fixed optimum.

The first two are different atom-mapping algorithms because they implement
different semantics, not optimizations of this operation. They must therefore
be exposed separately if later evidence justifies them. The third can preserve
the fixed semantics, but the first implementation does not use learned,
reaction-class, active-bond, neighborhood-similarity, or external-mapper
guidance. Such guidance should be considered only after benchmarks show that
the unguided exact case is inadequate.

### Constraint-satisfaction reading

Let each lhs atom `u` have a variable `X_u`. Its domain is every rhs atom whose
`ElementForm` is compatible under `ElementForm::is_compatible`, plus an
unmatched value. `Undetermined`, written `*`, is the lattice top and is
therefore compatible with every element form; two distinct literal elements
are incompatible. Distinct matched variables are subject to a global
all-different constraint; unmatched values may be represented by private
sentinels or an all-different-except convention.

Localized-bond conservation produces pairwise terms. Assigning `X_u = v` and
`X_w = z` determines whether the lhs bond `uw` corresponds to an rhs bond
`vz`. A corresponding pair is unchanged when its order forms are equivalent
and modified otherwise. Missing partners are deletions or additions. This
makes atom mapping a fixed lexicographic constraint-optimization problem, not
an ordinary linear assignment problem.

The fixed objective also has a direct partial quadratic-assignment reading.
For a completed candidate `m`, let `p(m)` be the number of lhs edges whose
mapped endpoints are joined by an rhs edge, and let `q(m)` be the number of
those paired edges whose order forms are equivalent. Then

```text
deletions     = |E_lhs| - p(m)
additions     = |E_rhs| - p(m)
modifications = p(m) - q(m)
total edits   = |E_lhs| + |E_rhs| - p(m) - q(m)
```

After maximum map cardinality is fixed, minimizing edits is therefore
equivalent to maximizing `p(m) + q(m)`. Two jointly selected atom pairs
contribute two units when their endpoints have equivalent bonds, one when both
bonds exist with different orders, and zero otherwise. Binary variables for
compatible atom pairs, injectivity constraints, and these pairwise rewards
give a partial quadratic assignment problem without changing the stated
semantics.

The generic algorithm families are:

| Formulation | Strength | Limitation here |
| --- | --- | --- |
| Direct finite-domain CSP / branch and bound | Natural partial-map variables, all-different propagation, anchors, lexicographic objectives, and problem-specific lower bounds. | Requires a purpose-built exact search, bounds, and careful output enumeration. |
| Partial quadratic assignment | Represents the fixed cardinality and pairwise bond reward directly; admits assignment, reformulation-linearization, and semidefinite bounds. | Exact solvers remain exponential and strong bounds add substantial implementation machinery. |
| Maximum or maximum-weight clique in an association graph | Mature bitset bounds; labeled sparse compatibility can work especially well. | The product graph can be large; partial unmatched values, bond modifications, and the lexicographic objective vector need extra encoding. |
| 0-1 ILP / MIP | Precise reference model, strong independent solver ecosystem, easy objective inspection. | External native solver and license/distribution concerns; all-optimum enumeration and symmetry expansion are not the default path. |
| SAT / MaxSAT / pseudo-Boolean | Auditable constraints and potentially certifiable optima. | Pair variables and quadratic bond terms expand the model; another runtime solver would be required. |
| QUBO / Ising | Direct pairwise objective and useful research comparison. | Hardware/annealing does not establish exactness by itself; all optima still require certified enumeration. |
| Brute-force permutations | Independent and extremely simple oracle. | Only practical for small fixtures and symmetry stress cases. |

McCreesh, Ndiaye, Prosser, and Solnon's comparison of
[clique and constraint models for maximum common subgraphs](https://doi.org/10.1007/978-3-319-44953-1_23)
is relevant beyond chemistry. Their CSP has one target-valued variable per
source vertex, an unmatched value, and injectivity constraints; their empirical
result is that neither direct CP nor clique reduction dominates every labeled
graph family. Atom mapping should therefore benchmark both readings rather
than treat a formulation as an algorithmic conclusion.

### Useful exact-search techniques

A direct solver can exploit:

- maximum bipartite matching over remaining compatible domains as an upper
  bound on additional matched atoms;
- smallest-domain and most-constrained-atom branching;
- lower bounds on unavoidable localized-bond edits;
- component decomposition when the objective proves the components
  independent;
- exact input automorphisms for a later search reduction, provided every
  pruned labeled mapping can later be expanded and visited.

The established all-different filtering literature, beginning with
[Régin 1994](https://www.constraint-programming.com/people/regin/papers/alldiff.pdf), explains why
injectivity should be a global propagation concern rather than only a late
duplicate check.

### Exact alternatives if direct search is inadequate

The fixed feasibility relation, objective, and all-labeled-optima result set do
not require one search formulation. Future exact implementations can preserve
that contract while changing the internal algorithm:

| Alternative | Exact use | Principal trade-off |
| --- | --- | --- |
| Stronger direct CSP / branch and bound | Add full all-different propagation, linear-assignment bounds on remaining quadratic reward, component decomposition, memoization, and exact orbit pruning with expansion. | Retains the simplest state model, but may still explore a large correspondence tree. |
| QAP-specific branch and bound or branch and cut | Optimize compatible assignment variables with the pairwise reward above; assignment, reformulation-linearization, or semidefinite relaxations provide stronger bounds. | Most direct alternate formulation, but the solver and its bounds are substantially more complex. |
| CP-SAT, pseudo-Boolean, or MIP | Linearize pair rewards, solve the two lexicographic terms in sequence, fix the optimum, and enumerate every solution at that score. | Valuable as an independent oracle or backend; model size, solver distribution, and all-solution enumeration may be costly. |
| Edge-weighted association-graph clique | Make compatible atom pairs vertices and place bond rewards between mutually consistent pairs. | Bitset clique algorithms may excel on bond-preserving cases, but the product graph can explode and an ordinary unweighted maximum clique is not equivalent to this objective. |
| A* or IDA* graph-edit search | Use an admissible assignment relaxation to explore partial correspondences in score order. | Can improve time to the first proved optimum, but A* is memory-heavy and edit-path multiplicity complicates enumeration of unique correspondences. |
| Component, separator, or treewidth dynamic programming | Solve decomposable sparse cases through boundary-mapping states and reconstruct all optima. | Potentially strong for suitable molecular structure, but unrestricted assignments couple both sides and the state space is exponential in the joint separator width. |
| Exact backend portfolio | Run complementary exact formulations with shared checked incumbents, while one backend supplies the proof and complete enumeration. | Useful after individual backends exist; coordination must not introduce a hidden default or weaken completeness. |

The first response to poor performance should be evidence-driven strengthening
of the direct solver, especially matching propagation, an assignment bound on
the quadratic reward, and proven component decomposition. A dedicated partial
QAP implementation is the most natural second native backend. A mathematical
programming formulation is useful earlier as an independent oracle, while
weighted clique and separator-based solvers should be selected by benchmarked
graph families rather than assumed to dominate generally. Classical exact QAP
work already demonstrates the use of linear-assignment subproblems as bounds
([Burkard and Derigs 1986](https://doi.org/10.1016/0377-2217(86)90303-6)).

Approximate or chemistry-selected mappings occupy a separate design branch.
They may return one correspondence, a ranked subset, or an optimum under a
mechanistic or learned objective, but they are not interchangeable backends
for the fixed exact operation. Even using one only as an incumbent or branch
order preserves exact semantics only when the native solver independently
proves the optimum and enumerates the complete labeled result set.

## Proposed structural contract

### Candidate correspondence

For sides `L` and `R`, a candidate is a `Correspondence<AtomId>` from `L` to
`R` satisfying:

- partial bijection and correct lhs/rhs atom counts;
- `ElementForm::is_compatible` for every matched pair.

Literal element equality is the ground special case, not the general
compatibility rule. In particular, `*` may correspond to a literal element or
another `*`; the atom correspondence records the identification while the
element-field delta records any representational refinement or change.

Isotope mass, charge, implicit hydrogen count, lone pairs, unpaired electrons,
stereo configuration, constraints, and overlay values are neither atom-identity
constraints nor objective terms. They may legitimately change across a
derivation and remain available when the selected atom map is induced into a
complete `MoleculeCorrespondence`. Element underdetermination is not an
operation error.

### Objective

The fixed score compares candidates lexicographically:

1. maximize the number of matched atoms;
2. among those candidates, minimize the number of localized covalent-bond
   edits induced between the two sides.

Because the input graphs are simple, a lhs edge has at most one rhs edge over
the images of its endpoints. A lhs edge without that partner is one deletion;
an rhs edge without a lhs partner is one addition; and a paired edge whose
order forms are not equivalent under `NumForm::equiv` is one modification.
Edges incident to unmatched nodes are therefore deletions or additions. A
modification counts once rather than as a deletion plus an addition, and its
unit cost does not depend on numerical order difference: `1` to `2` and `1` to
`3` each cost one.

Only the sum of additions, deletions, and modifications enters the second
objective term. Distinct optimal correspondences can therefore have the same
total edge-edit cost with different category decompositions; the categories
remain independently calculable diagnostics, not further tie-breakers.

The first term prevents a solver from deleting and recreating inconvenient
atoms to obtain an artificially small reaction center. Whenever a total
element-compatible bijection exists it requires one. Otherwise it retains the
largest element-compatible partial bijection.

Bond charge, unpaired electrons, bond constraints, every non-element atom
field, and all overlays remain outside the score. There are no
element-dependent, bond-dependent, reaction-class, or mechanism-derived
weights. This deliberately modest objective matches the minimum-induced-bond
change reading used by exact external formulations and is easy to inspect; it
does not claim that the smallest reaction center is the true mechanism.

### Result set

The semantic result is the set of every labeled candidate with the globally
optimal fixed score. Output order may be deterministic
for a fixed representation and algorithm, but it is not a canonical or
chemistry-ranking contract.

An empty-compatible pair has one optimum: the empty correspondence with the
correct side counts. An unbalanced reaction is not an error. The graph-core
operation is defined for simple inputs and returns `NonSimpleGraphError` when
either supplied `Graph` contains a self-loop or parallel edges. It checks both
inputs before evaluating either caller-supplied closure. Molecule integrity
establishes that the graph-IR wrapper supplies simple molecular topologies.

## Symmetry contract

Let `Aut(L)` and `Aut(R)` be exact automorphism groups preserving element
compatibility and localized-bond order equivalence.
They act on a mapping `m` by

```text
m' = beta compose m compose alpha^-1
```

for `alpha` in `Aut(L)` and `beta` in `Aut(R)`. Mappings in one orbit may induce
isomorphic condensed reaction graphs, but they are still distinct labeled
`Correspondence` values.

The operation must visit all of them. In particular:

- no canonical-rank tie-break selects one symmetric atom;
- no symmetry-breaking constraint may remove output mappings unless exact
  orbit expansion restores them;
- no `first`, `best`, or output order implies a chemical preference;
- equivalence-class counts and representative condensed graphs are diagnostics,
  not the primary return value.

This contract can produce factorial output for explicit hydrogens, repeated
identical components, and highly symmetric molecules. That is an inherent
property of the requested result, not an algorithm defect. The primary API must
therefore be a visitor with early termination. An eager collector is a
convenience for bounded cases. There should be no hidden result cap or timeout.

The first implementation avoids symmetry pruning. A later optimization may
enumerate orbit representatives internally and expand them through graph-core's
exact automorphism generators. Approximate WL cells are useful branch-ordering
hints but cannot establish complete or disjoint orbits. Overlay distinctions
do not split first-version objective degeneracy because overlays are outside
both feasibility and score.

## Search design sketch

The implementation is an exact, two-pass finite-domain branch-and-bound search
in `umol-graph-core::algorithms::graph_edit`:

- the optimization pass finds the lexicographically optimal matched-atom and
  localized-bond-edit score;
- the enumeration pass fixes that score and visits every satisfying atom
  assignment;
- all-different propagation and bipartite matching bounds enforce and bound the
  partial bijection;
- an admissible lower bound on unavoidable localized-bond edits prunes branches
  that cannot reach the optimum;
- branching uses only generic domain structure such as smallest remaining
  domain, without chemistry-guided candidate selection;
- the first implementation performs no symmetry pruning and accepts no
  external incumbent.

The two passes are important for the public delivery contract. A one-pass
optimizer can discover a better incumbent after it has emitted earlier
solutions, while buffering every incumbent reproduces eager output-sized
storage. Once the optimum is fixed, the second pass has ordinary visitor
semantics and may stop on `ControlFlow::Break`.

The direct CSP keeps unmatched atoms, the lexicographic score, and all-solution
enumeration visible. An exhaustive brute-force algorithm supplies small-case
differential evidence throughout the implementation plan. At closeout it must
not remain hidden in property-test support: if it has genuine use as a bounded
baseline or separately selectable algorithm, it moves into
`algorithms::graph_edit` with ordinary tests and benchmarks; otherwise it is
deleted after disagreements have been minimized into fixed regression cases.
Association-graph, MIP, and external mapper formulations remain development
comparisons, not first-version backends. The operation introduces no public
solver abstraction beyond algorithms that survive that explicit disposition.

## Public surface

Graph-core owns the generic simple-graph operation. The selected names omit
`try_` and return `Result` for the explicit input-domain error:

```text
MinimumEditAlgorithm::BranchAndBound

lhs.visit_minimum_edit_correspondences(
    rhs,
    &mut node_compatible,
    &mut edge_equivalent,
    algorithm,
    visitor,
) -> Result<ControlFlow<B>, NonSimpleGraphError>

lhs.enumerate_minimum_edit_correspondences(
    rhs,
    &mut node_compatible,
    &mut edge_equivalent,
    algorithm,
) -> Result<Vec<Correspondence<NodeId>>, NonSimpleGraphError>
```

The visitor receives a borrowed `&[(NodeId, NodeId)]` over search state. The
eager operation constructs owned correspondences by collecting the visitor.
Both closures are evaluated as stable relations for one operation; the kernel
may precompute their values and does not expose their call order as a contract.
The graph-core operation checks both graphs for simplicity before evaluating
either closure. On success the delivery payloads remain `ControlFlow<B>` and
`Vec<Correspondence<NodeId>>` inside `Result`.

Graph-IR exposes the fixed molecular specialization without a configuration
object or a second algorithm enum:

```text
lhs.visit_atom_mappings(
    rhs,
    MinimumEditAlgorithm::BranchAndBound,
    |atoms: Correspondence<AtomId>| ...,
) -> ControlFlow<B>

lhs.enumerate_atom_mappings(
    rhs,
    MinimumEditAlgorithm::BranchAndBound,
) -> Vec<Correspondence<AtomId>>

Reaction::from_sides(lhs, rhs, atoms)
    -> Option<Reaction>
```

The semantic roles are:

- `Correspondence<AtomId>` remains the atom-map carrier;
- `MoleculeCorrespondence` remains the induced aggregate carrier;
- `Reaction` remains the central lhs-plus-deltas reaction representation;
- graph-core owns the exact graph search and returns `NonSimpleGraphError` for
  either non-simple input;
- graph-IR supplies element compatibility and localized-bond order
  equivalence, converts node ids to atom ids, and relies on molecule integrity
  for the graph-core precondition;
- algorithm selection is explicit at both operation boundaries;
- no public optimizer/session/result-wrapper layer is required for the happy
  path.

Returning correspondences from the output-sensitive visitor avoids constructing
a reaction for every symmetric mapping. A caller that selects a mapping passes
it to `Reaction::from_sides`, which checks it against the supplied molecules,
induces the complete entity correspondence, and records the transformation as
lhs-anchored deltas. The supplied rhs may be reindexed into that reaction frame;
the atom-mapping operation itself retains every distinct labeled correspondence.

Atom mapping does not construct `ReactionDerivation`. Reaction application and
the future of that result type are separate design questions recorded in doc
204.

If Python exposure follows, an iterator or callback-equivalent must preserve
the same all-optima and early-stop reading. Python must not silently collapse
symmetry classes or substitute RXNMapper as a hidden backend.

## Evaluation design

### Correctness fixtures

The fixtures need to distinguish labeled maps from equivalence classes:

- identity and pure atom-field changes;
- wildcard/literal, wildcard/wildcard, overlapping-set, and disjoint-element
  compatibility cases;
- one bond creation, deletion, and order modification;
- bond charge, unpaired-electron, and constraint differences that do not alter
  the score;
- balanced substitution, rearrangement, and disconnected transfer;
- unbalanced sides with unmatched atoms on either side;
- asymmetric isotope annotation and explicit hydrogen cases;
- benzene, carboxylate, phosphate, and other local symmetries;
- repeated identical components and component exchange;
- an equal-score pair that induces distinct condensed reaction graphs;
- overlay/stereo-bearing sides whose extra entities do not change the result
  set;
- graph-core self-loop and parallel-edge inputs rejected before callbacks.

Small cases should be exhaustively enumerated by independent permutations and
compared as sets. Current MCES can independently cross-check balanced
localized-bond cases where the objectives coincide. Mathematical-programming
comparisons remain deferred.

### Semantic properties

Required laws include:

- every output satisfies partial-bijection, compatibility, and aggregate
  induction;
- no valid candidate has a better lexicographic score;
- no two visited outputs are structurally equal correspondences;
- lhs/rhs id remapping transports the output set bijectively;
- swapping sides and reversing every correspondence preserves the score and
  result set;
- molecule automorphisms generate expected output maps rather than deleting
  them;
- visitor completion equals eager collection as sets;
- visitor early termination emits an exact prefix without changing already
  emitted values.

### External comparison

The initial Rhea comparison used the saved RXNMapper output as its own common
atom frame and reported separately:

- parse and correspondence-contract failures;
- exact-solver coverage and timeouts, with no silent partial answer;
- external candidate score relative to the exact fixed optimum;
- map-label equality only after the same atom frame is established;
- known mechanism disagreements as curated annotations, never as an inferred
  objective failure.

The broader normalized comparison, reaction-span/CGR equivalence, symmetry-
quotiented results, and additional external formulations now belong to the
shared test-corpus work in doc 205. RXNMapper, Indigo, AMNet if practical,
AAM-Ising, and reactmap remain development comparisons rather than acceptance
dependencies. LocalMapper remains paper-only background.

### Performance evidence

Measurements should expose both optimization and enumeration behavior:

- time to prove the optimum;
- time to first optimum after the proof pass;
- median, p95, and maximum inter-output delay;
- total labeled-output count and equivalence-class count;
- peak memory;
- search nodes, domain deletions, matching-bound calls, and incumbent quality;
- explicit-hydrogen versus implicit-hydrogen representations;
- low-symmetry Rhea cases, high-symmetry molecules, repeated components, and
  adversarial equal-score rearrangements.

No median-only corpus benchmark is sufficient. Exact mapping is combinatorial,
and the hard tail and symmetry-expanded output volume determine whether a
second algorithm or an explicit search-budget result is necessary.

## Deferred extensions

The first implementation deliberately does not settle or reserve interfaces
for:

- atom-field, overlay, or stereo objective terms and any corresponding levels
  or weights;
- anchored completion;
- configurable costs, incumbent injection, or search budgets with incomplete
  bounds;
- QAP, maximum-weight-clique, A*/IDA*, separator-DP, mathematical-programming,
  or exact-portfolio backends;
- chemistry-selected feasible sets, objectives, rankings, and incomplete
  result semantics as separate atom-mapping algorithms;
- automorphism pruning with exact orbit expansion;
- Python delivery.

Each requires evidence from the fixed baseline. None is a prerequisite for
the implementation below.

## Non-simple graph contract

`Graph` can represent loops and parallel edges, while the fixed edit score is
defined only for simple graphs. Both graph-core operations therefore return
`Result<_, NonSimpleGraphError>`, reusing graph-core's existing public error
type. They inspect the lhs and rhs before evaluating either compatibility
closure or starting either search pass, and return the error when either graph
contains a self-loop or parallel edges. They do not discard loops, select one
parallel edge, simplify an input, or define multigraph edit semantics.

The public delivery names remain `visit_minimum_edit_correspondences` and
`enumerate_minimum_edit_correspondences`; the input-domain error is expressed
by `Result`, not a `try_` prefix. The graph-IR molecule operations remain
infallible because molecule integrity establishes simple localized-bond
topology before a `Molecule` is published.

## Closeout summary

The first exact structural atom-mapping operation is implemented and verified.
Graph-core provides explicit branch-and-bound and exhaustive minimum-edit
algorithms over simple graphs; graph-IR specializes the operation to molecule
element compatibility and bond-order equivalence; both visitor and eager APIs
return every labeled optimum. The exhaustive comparator was promoted into the
ordinary algorithm module rather than retained as a hidden property-test
implementation. Reaction construction remains a separate checked lifting step.

The initial external characterization supplied the evidence needed to stop
treating further comparison as implementation closeout. It showed both limits
that matter next: exact proof coverage deteriorates quickly beyond small
reactions, and the fixed objective can prefer a chemically wrong mapping even
when solved exactly. The implemented operation therefore remains a precise A0
structural baseline, not a finished chemistry mapper.

Doc [205](205-mapping-test-corpus-2026-08-20.md) owns the continuing work: a
normalized atom-mapping test corpus, external and network-derived evidence,
objective analysis, symmetry-aware comparisons, and exact-engine performance.
That corpus is also the first case study for doc 201's shared external
representation, columnar query, SVG, and Jupyter stack; it must not become a
one-off atom-mapping harness.
